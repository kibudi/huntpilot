huntpilot

A job tracker that watches the boards back.

Job boards tell you what is open right now. They never tell you what changed — and the changes are what matter when you are the one applying. huntpilot sweeps company job boards on a schedule and reports the difference.

The questions no board answers

It closed on you

The role you applied to has disappeared from the board. It is filled. Stop waiting.

Still open, still silent

You applied 30 days ago and the posting is still live. Silence is not rejection.

Reposted again

The same job, listed every six weeks. Churn, or a spec nobody can meet.

None of that is answerable from a single snapshot. It needs board state stored over time and joined against your own application log — which is the other half of this app.

reconcileThe product. Still listed, newly appeared, or absent — compared against the last sweep.free

Every gate is free and local. No model call, no paid API, no scraping — the boards publish this themselves.

The dashboard

Every role the sweep kept, how long it has been listed, and whether it is already in the pipeline. Chips narrow by region and by open or closed; Track copies a posting into the applications list.

How it fits together

The worker reaches the database directly rather than through the API: it is the same codebase run with a different command, and a round trip over HTTP would buy nothing.

Decisions worth defending

  • Closure is inferred from repeated absence, never from one. No board announces that a role was filled; the entry simply stops coming back. Boards also intermittently drop live entries, so a posting must be missing twice before it counts as closed — telling you a job is gone while it is still taking applications is the one failure this cannot afford.
  • A board that fails to load is skipped, not treated as empty. Since absence is the signal, reconciling an empty list after a failed fetch would mark every one of that company's roles as heading for closed.
  • One document per posting for its whole life, never one per sweep. The collection grows with the market rather than with elapsed time.
  • The description is stored, not the score. Scores depend on a vocabulary that changes as it is corrected, so storing the text keeps every posting rescorable without fetching a board again.
  • The dashboard never decides what counts as Israel. It used to keep its own copy of the location list; the two drifted, and postings in the missing cities were stored and then quietly left out of the count.
